# supertick в Kimi и Codex (2.0.0-alpha)

С 2.0 командный прогон можно вести не только из Claude Code. Ведущим может быть Kimi Code CLI или
Codex CLI, а роли команды можно раздать по разным CLI и моделям. В Claude Code всё осталось как в
1.1.1: те же команды, тот же `~/.claude/agent-teams.json`, сборка отличается от 1.1.1 только файлами из
`tools/tests/snapshots/plugin-1.1.1.changes`.

| Среда | Уровень | Как ведущий ждёт | Исполнители по умолчанию | Состояние |
|---|---|---|---|---|
| Claude Code | L3 | фоновый `supervisor-wait.sh`, пробуждение по концу задачи | субагенты Claude, участники с сообщениями | 1.1.1, без изменений |
| Kimi Code CLI | L2 | фоновый `supervisor-wait.sh`, Kimi будит по концу фоновой задачи | родные субагенты Kimi (`supertick-<роль>`) | alpha |
| Codex CLI | L1 | `supervisor-wait.sh` на переднем плане, вызов за вызовом, внутри одного хода | движок `codex` с моделью ведущего | alpha |
| OpenCode | — | — | — | только как движок; адаптер — beta |

Kimi и Codex работают по общему протоколу `hosts/shared/LEAD.md`: сообщений между исполнителями нет,
цикл (кодер → ревью → правка → коммит → приёмка) ведёт сам ведущий, продолжая того же исполнителя.
Каталог прогона — `<репозиторий>/.supertick/teams/feature-<имя>/`.

## Установка

Из клона репозитория, ветка `universal`:

```bash
tools/install-kimi.sh      # Kimi: ~/.kimi-code/plugins/managed/supertick, запись в plugins/installed.json
tools/install-codex.sh     # Codex: локальный маркетплейс supertick-local, codex plugin add supertick@supertick-local
```

Повтор безвреден и обновляет установленную копию. Удалить — тот же скрипт с `--uninstall`. Новые навыки
среда видит после перезапуска сессии. Нужны `bash`, `python3` (только stdlib), `git`; Linux или macOS.

## Подключение: профиль

Навык `supertick:setup` (в Kimi и в Codex) показывает установленные CLI и их модели, задаёт до четырёх
вопросов и пишет профиль в `~/.config/supertick/config.json` (или в `$SUPERTICK_CONFIG`):

- **ведущий** — среда и модель;
- **состав команды** — «всё на модели ведущего», «код и ревью на разных моделях» или «по группам ролей»
  (кодеры, рецензент, архитекторы и техлид, исследователи, проверяющие);
- **второе мнение** — другая модель для чувствительных задач или «выключено»;
- **имя профиля**.

Перед записью навык показывает таблицу «роль → движок → модель → доступ». Это ровно то, что исполнит
прогон: роль без назначения записывается в профиль явно (`null` — родной исполнитель среды), поэтому
роли из прежнего `~/.claude/agent-teams.json` профиль не перекрывают. Сам `agent-teams.json` диалог не
меняет никогда.

Без человека (скрипты, CI) — тот же диалог файлом ответов:

```bash
python3 <корень набора>/scripts/supertick-setup.py plan  --answers answers.json   # таблица, без записи
python3 <корень набора>/scripts/supertick-setup.py apply --answers answers.json   # запись профиля
```

Формат файла ответов — в шапке `supertick-setup.py`. `supertick-setup.py launch <профиль>` печатает
команду запуска ведущего.

**Проба ведущего.** `supertick-setup.py lead-probe <профиль>` — 15–20 минут вызовов модели на стенде с
мок-исполнителями: держит ли модель ведущего протокол (запуски через `run-engine.sh`, ожидание
скриптом, цикл ревью, приёмка, не трогает код сама). Итог пишется в профиль и показывается в диалоге.
Проверены: Kimi `kimi-code/k3` и Codex `gpt-5.6-sol` — passed.

## Запуск прогона

**Kimi** — в сессии `kimi -m <модель>` (или `kimi -p` без человека):

```
Используй навык supertick:team-feature с аргументами: «<фича>» --complexity=simple
```

**Codex** — ведущий запускается без песочницы, иначе исполнители `codex exec` из его shell не стартуют:

```bash
codex --sandbox danger-full-access -m gpt-5.6-sol
# или без человека:
codex exec --sandbox danger-full-access -m gpt-5.6-sol --json -- 'Используй навык supertick:team-feature с аргументами: …'
```

Ограничения ролей держат песочницы исполнителей: роли чтения — `codex exec --sandbox read-only`, кодер —
`workspace-write` с записью в каталоги `.git` (иначе он не закоммитит). Поэтому на Codex роль без
назначения идёт движком `codex`, а не родным субагентом: у `spawn_agent` своей песочницы нет.

Аргументы те же, что в Claude Code: `--complexity=simple|medium|complex`, `--coders=N`, `--no-research`,
`--force-team`, `--engines=off`.

## Чем отличается от Claude Code

- **Ожидание.** Kimi будит ведущего по концу фоновой задачи, как Claude Code: ведущий спит вне хода. Codex не будит: прогон идёт одним длинным ходом, ведущий ждёт внутри него
  `supervisor-wait.sh --max 1500` и снова. Закончил ход раньше сводки — прогон встал.
- **Одно ожидание на прогон.** `kimi -p` не выходит, пока жива хоть одна фоновая задача. Новое ожидание
  гасит прежнее само, на финише ведущий гасит последнее (`lead:wait-stop`).
- **`.git` под присмотром.** Кодер может писать в `.git`, значит и в `.git/hooks`, а хук потом исполнит
  владелец вне песочницы (риск R11). `git-guard.py` снимает отпечаток `.git/hooks` и `.git/config` в
  начале прогона и сверяет в конце; изменение — строка ⚠️ и первый пункт ручных проверок, ведущий
  ничего не откатывает.
- **Нет браузерного проверяющего и живого веб-поиска** вне Claude Code: такие пункты уходят в ручные
  проверки; `web-researcher` работает только на движке с живым поиском.
- **Тихой замены нет.** Роль, чей CLI не найден, уходит по `fallback` (`host` — на исполнителя среды,
  `fail` — остановка) с видимой строкой ⚙️.

## Диагностика

```bash
python3 <корень набора>/scripts/supertick-doctor.py --host kimi     # версия, среда, конфиг, CLI, профиль
python3 <корень набора>/scripts/engine-config.py resolve --host kimi   # кто исполнит каждую роль
```

Каталог прогона — всё состояние: `PLAN.md`, `state.md`, `runs/`, `reports/`, `engine/`, `ledger.jsonl`
(каждый вызов движка с ролью, движком и моделью). После потери контекста ведущий восстанавливается по
нему и одному тику.

## Известные ограничения alpha

- Квота подписки модели — общий ресурс всей команды на родных субагентах: прогон SIMPLE в Kimi на
  родных субагентах расходует заметную часть пятичасового окна Kimi Code, исчерпание обрывает прогон
  (`APIProviderQuotaExhaustedError`). Роли на других CLI разгружают квоту.
- Ответ cursor `composer-2.5` бывает вступительной репликой вместо отчёта; ведущий продолжает
  исполнителя, как велит протокол, но это лишний вызов.
- Роли и навыки написаны по-русски; лента прогона — на языке пользователя.
- Прогоны приёмки и их итоги — `docs/trials/2.0-alpha-runs.md`; разбор сред — `docs/spikes/`.
