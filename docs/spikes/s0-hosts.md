# Спайк S0: что умеют среды

Задачи S0-K и S1 из ТЗ редакции 4.1 (карточка 121-567). Здесь — Kimi Code CLI. OpenCode и Codex CLI
будут дописаны задачей S0-OC.

Пометки: **[запуск]** — проверено действием, образец вывода лежит в `fixtures/kimi/`;
**[док]** — со слов Kimi по его официальной документации (встроенный навык `check-kimi-code-docs`),
действием не проверено.

## Kimi Code CLI 2.5.3

Проверено 10–11.11.2026 на Linux x64. Установка: `curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash`
(бинарь `~/.kimi-code/bin/kimi`). Пакет PyPI `kimi-cli` снят с поддержки. Вход: `kimi login` (код устройства).

### Таблица примитивов

| Примитив | Итог |
|---|---|
| headless-запуск | **[запуск]** `kimi -p "<текст>"`, короткий ответ за ~12 с |
| JSON-вывод | **[запуск]** `--output-format stream-json` — строки JSONL: `{"role":"meta","type":"system.version"}`, `{"role":"assistant","content":…}`, `{"role":"assistant","tool_calls":[…]}`, `{"role":"tool","tool_call_id":…,"content":…}`, в конце `{"role":"meta","type":"session.resume_hint","session_id":…}`. Текстовый режим печатает и рассуждение модели — для разбора не годится |
| id и продолжение сессии | **[запуск]** `session_<uuid>` в поле `session_id`; `kimi -S <id> -p …` помнит контекст. В подсказке CLI печатает `-r`, в справке описан `-S` |
| ошибки | **[запуск]** код выхода 1, в stdout только строка версии, текст в stderr: `error: failed to run prompt: Model "…" is not configured in config.toml.` / `Session "…" not found.` |
| режим записи | **[запуск]** в `-p` файлы пишутся и команды запускаются без подтверждений. `--auto`, `--yolo`, `--plan` с `-p` не сочетаются |
| режим чтения | **[запуск]** `kimi -p --agent-file <файл>` с `tools: [Read, Grep, Glob]`: записать файл агент не может, инструментов записи и shell у него нет |
| выбор модели | **[запуск]** `-m <алиас>`; алиасы и уровни усилия — в `~/.kimi-code/config.toml`. По подписке: `kimi-code/kimi-for-coding` (по умолчанию), `kimi-code/kimi-for-coding-highspeed`, `kimi-code/k3`, `kimi-code/k3-256k`, `kimi-code/k3.1-pro`, `kimi-code/k3.1-pro-highspeed` |
| чужие провайдеры внутри Kimi | **[док]** `kimi provider add <url>`, `kimi provider catalog`. Не пробовали |
| shell из сессии | **[запуск]** передний план: по умолчанию 60 с, максимум 300 с. Фон (`run_in_background`): до 86400 с |
| фоновые задачи | **[запуск]** `Bash(run_in_background=true)` → `task_id`; `WaitFor`, `TaskList`, `TaskOutput`, `TaskStop` |
| пробуждение ведущего | **[запуск]** после конца хода завершение фоновой задачи приходит новым ходом. Работает и в `-p`: процесс живёт, пока есть фоновые задачи |
| родные субагенты | **[запуск]** `Agent(prompt, description, subagent_type, run_in_background, resume)`. Встроенные типы: `coder`, `explore`, `plan` |
| фоновые субагенты | **[запуск]** два субагента в фоне; уведомления пришли двумя отдельными ходами, по одному на субагента |
| продолжение субагента | **[запуск]** `Agent(resume="agent-0", prompt=…)` — субагент вспомнил кодовое слово из первого задания. При `resume` тип не указывается |
| свои типы агентов | **[запуск]** Markdown с frontmatter `name`, `description`, `tools` в `.kimi-code/agents/` проекта: тип виден инструменту `Agent`, ограничение инструментов действует. **[док]** ещё каталоги `~/.kimi-code/agents/`, `~/.agents/agents/`, `.agents/agents/`; поля `disallowedTools`, `subagents`, `override`; поле `model` игнорируется |
| модель субагентов | **[док]** `[secondary_model]` в `config.toml`: одна модель или пул; при пуле у `Agent` появляется параметр `model`. Не пробовали |
| сообщения между агентами | нет: такого инструмента в списке нет. Общение — через ведущего (`resume`) и файлы |
| вопрос человеку | **[запуск]** в `-p` инструмент `AskUserQuestion` запрещён (режим auto: «вопросы решать самостоятельно»). В интерактивной сессии работает: проверено владельцем вручную 11.11.2026, вопросы приходят с вариантами ответа |
| навыки | **[запуск]** `--skills-dir <dir>` и `<имя>/SKILL.md` с `name`, `description`; вызываются инструментом `Skill`. **[док]** каталоги `~/.kimi-code/skills/`, `~/.agents/skills/`, `.kimi-code/skills/`, `.agents/skills/`; `/skill:<имя>`; `${KIMI_SKILL_DIR}`; `$ARGUMENTS` |
| плагины | **[запуск, частично]** плагин с манифестом `kimi.plugin.json` (`name`, `version`, `description`, `skills`, `agents`), оказавшись в `~/.kimi-code/plugins/managed/<id>/` и в `plugins/installed.json`, работает: навык виден как `<plugin-id>:<skill>`, агент — по своему имени. Официальная установка — `/plugins install <путь или url>` в интерактивной сессии: проверена владельцем вручную 11.11.2026, плагин-пустышка установился и заработал после перезапуска Kimi |
| установка без интерактива | **[запуск]** `kimi -p "/plugins install …"` слэш-команду не исполняет: текст уходит модели как обычный запрос. Надёжный путь без интерактива — копировать навыки в `~/.kimi-code/skills/` и агентов в `~/.kimi-code/agents/` |
| маркер среды | **[запуск]** своей переменной окружения нет: дочерним командам Kimi добавляет только `GIT_TERMINAL_PROMPT` и `NO_COLOR` |
| прочее | инструменты `CronCreate/List/Delete`, `CreateGoal/GetGoal/UpdateGoal/SetGoalBudget`, `WebSearch`, `FetchURL`, `TodoList`; hooks в `config.toml` и `AGENTS.md` — **[док]** |

### Проба ведущего на длинном тексте

Стенд собирает `tools/spikes/build-lead-probe.sh <каталог>`: пустой git-репозиторий, мок-движок
`scripts/mock-engine.sh` (кодер коммитит строку, рецензент на первом круге даёт FAIL, на втором PASS,
приёмка PASS) и навык `lead-probe` на 596 строк. В навыке 10 правил ведущего и справка `engines.md`
из 1.1.1 как нагрузка; одно обязательное правило спрятано в середине справки (строка 353).
Проверки — `check.sh`, только по файлам.

| Модель | Время | Итог |
|---|---|---|
| `kimi-code/k3` | 165 с | 10 из 10 |
| `kimi-code/kimi-for-coding` (по умолчанию) | 135 с | 10 из 10 |

Обе модели: завели `state.md` и `PLAN.md` в заданном формате, нашли правило из глубины справки,
запускали движок только в фоне, заканчивали ход строкой ожидания и просыпались сами, прошли цикл
кодер → FAIL → кодер → PASS → приёмка в правильном порядке, исходники и git руками не трогали,
написали отчёт. По одному прогону на модель: это проверка «справляется ли вообще», а не статистика.

### Вывод

Kimi CLI — уровень **L2**: родные субагенты со своими типами и продолжением, фоновое ожидание с
пробуждением, навыки. Сообщений между агентами нет, цикл ведёт ведущий.

Следствия для задач:
- **F4, пресет `kimi`:** `kimi -m {model} --output-format stream-json -p …`; сессия — поле `session_id`
  строки `session.resume_hint`; продолжение `-S {session}`; ошибка — код выхода 1 и текст в stderr;
  чтение — `--agent-file` с профилем без записи.
- **D6, приёмка:** профиль только из `Read, Grep, Glob` команды запускать не может. Приёмщику нужен
  `Bash` плюс запрет записи другим способом (свой профиль без `Write`/`Edit` и правила
  `[[permission.rules]]`) — проверить в F4.
- **F5–F6, диалог:** в `-p` вопрос человеку недоступен, значит диалог идёт либо в интерактивной сессии,
  либо в терминале через `supertick-setup.py`.
- **H1, плагин Kimi:** установщик кладёт навыки и агентов в пользовательские каталоги Kimi;
  манифест `kimi.plugin.json` прикладывается для тех, кто ставит через `/plugins install`.
- **Осторожность:** в `-p` Kimi действует без подтверждений и идёт далеко. На запрос
  `/plugins install <путь>` модель сама разобрала свой бинарь и вручную записала реестр плагинов в
  `~/.kimi-code/plugins/`. Задания движку должны быть узкими, а профиль — с минимальным набором
  инструментов.

### Не проверено

- пул `[secondary_model]` и чужие провайдеры внутри Kimi;
- расход подписки на настоящем командном прогоне;
- ведущий на реальном протоколе с несколькими задачами параллельно (проба — одна задача).
