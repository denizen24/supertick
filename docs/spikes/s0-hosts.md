## Kimi Code CLI 2.5.3

Проверено 10–11.11.2026 на Linux x64. Установка: `curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash`
(бинарь `~/.kimi-code/bin/kimi`). Пакет PyPI `kimi-cli` снят с поддержки. Вход: `kimi login` (код устройства).

### Вывод

Kimi CLI — уровень **L2**: родные субагенты со своими типами и продолжением, фоновое ожидание с
пробуждением, навыки. Сообщений между агентами нет, цикл ведёт ведущий.

Следствия для задач:
- **F4, пресет `kimi`:** `kimi -m {model} --output-format stream-json -p …`; сессия — поле `session_id`
  строки `session.resume_hint`; продолжение `-S {session}`; ошибка — код выхода 1 и текст в stderr;
  чтение — `--agent-file` с профилем без записи.
- **D6, приёмка:** профиль только из `Read, Grep, Glob` команды запускать не может. Приёмщику нужен
  `Bash` плюс запрет записи другим способом (свой профиль без `Write`/`Edit` и правила
  `[[permission.rules]]`) — проверить в F4.
- **F5–F6, диалог:** в `-p` вопрос человеку недоступен, значит диалог идёт либо в интерактивной сессии,
  либо в терминале через `supertick-setup.py`.
- **H1, плагин Kimi:** установщик кладёт навыки и агентов в пользовательские каталоги Kimi;
  манифест `kimi.plugin.json` прикладывается для тех, кто ставит через `/plugins install`.
- **Осторожность:** в `-p` Kimi действует без подтверждений и идёт далеко. На запрос
  `/plugins install <путь>` модель сама разобрала свой бинарь и вручную записала реестр плагинов в
  `~/.kimi-code/plugins/`. Задания движку должны быть узкими, а профиль — с минимальным набором
  инструментов.

Проверено 12.11.2026 на Linux x64, Node 20.20.2. Установка: `npm install -g @openai/codex`. Вход:
`codex login` (на сервере без браузера — `codex login --device-auth`); на момент спайка — вход по ChatGPT.

### Вывод

Codex CLI — уровень **L1 с родными субагентами**: shell, файлы, навыки, субагенты с продолжением
(`send_input`) и долгое ожидание (`wait_agent` до часа, опрос `write_stdin` до 5 минут), но ведущего никто не
будит. Как ведущий Codex держит протокол на длинном тексте, если ждёт внутри хода и ему можно писать в `.git`.

Следствия для задач:
- **Общий протокол (P2, `hosts/codex/primitives.md`):** ожидание — внутри хода (`wait_agent` с большим
  `timeout_ms` для субагентов, `supervisor-wait.sh` или опрос сессии `exec_command` для движков). Строки
  «закончи ход и жди пробуждения» для Codex недопустимы. Ведущий обязан довести цикл до конца в одном ходе.
- **Кодер (F4, H4):** пресет `codex` для роли с коммитом передаёт каталоги `.git` записываемыми
  (`{git_flags}` в `engine-config.py`). Для родного субагента-кодера режим наследуется от ведущего: ведущий
  Codex запускается с тем же `writable_roots`.
- **Роли чтения на родных субагентах:** ограничить субагента нельзя ни типом, ни песочницей (D6 держится на
  тексте задания). Надёжное чтение — внешний вызов `codex exec --sandbox read-only` (пресет `codex`) или другой
  движок в режиме чтения.
- **Пресет `codex` 1.1.1 исправлен:** `--` перед промптом (иначе бриф с `---` падает), `-m`, усилие и режим на
  продолжении (иначе `resume` молча берёт другую модель — нарушение D5), `--skip-git-repo-check` у `resume`,
  `--json` вместо текста с баннером в ответе. Разбор JSONL — в `run-engine.sh`.
- **Вопрос человеку:** в `exec` недоступен, как у Kimi в `-p`. Диалог — в терминале через
  `supertick-setup.py`, либо в интерактивной сессии (не проверено).

### Риски и осторожность

- **Запись в `.git` открывает запись в `.git/hooks`.** Движок с записываемым `.git` смог создать
  `.git/hooks/pre-commit-probe`; хук потом исполнит владелец вне песочницы. Мера: кодер Codex работает в
  отдельном git-worktree, после прогона сверяются `.git/hooks` и `.git/config`. Ограничить запись подкаталогами
  `.git` нельзя: `index.lock` создаётся в самом каталоге.
- На сервере нет `bubblewrap`: песочница всё равно блокирует запись (проверено), но Codex предупреждает.
  Установка пакета — решение владельца.
- Прогон ведущего на `luna` показал, что слабая модель пропускает правило из середины длинного текста: проба
  ведущего (п. 4.5 ТЗ) нужна и для Codex.

### Не проверено

- `multi_agent_v2` и чем заменяются инструменты субагентов;
- интерактивная сессия Codex: вопрос человеку, пробуждение ведущего от фоновой задачи в TUI;

### Риски и осторожность

- Ведущий без `timeout` у долгого ожидания получит обрыв на 120 с — в `primitives.md` OpenCode указать параметр.
- `~/.claude/skills/` подхватывается в каждый запуск: чужие навыки владельца видны ведущему OpenCode.
- Бесплатные модели Zen могут исчезнуть или упереться в лимиты — для R4 нужен запасной вариант.
- **[запуск, H3] Отказ в правах обрывает `opencode run` на месте:** правило `ask` (например `external_directory` для файла
  вне проекта) в headless отклоняется, и после отказа модель уже не отвечает — прогон кончается без сводки.
  Ведущему вне проекта можно трогать только каталог навыка (каталоги навыков OpenCode открывает сам).
- **[запуск, H3] Каталог проекта — из `PWD`, а не из cwd процесса:** запуск с унаследованным `PWD` уводит ведущего в
  чужой репозиторий. Запускать из каталога проекта с верным `PWD`.
- **[запуск, H3] Лимит бесплатных моделей Zen** («Free usage limit reached», 14.11.2026 после ≈1,5 ч проб) пишется только в
  `~/.local/share/opencode/log/opencode.log`, а `opencode run` не выходит — молча висит. Снаружи это видно лишь как молчание.
