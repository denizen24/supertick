## Третий прогон: внедрённый отказ ревью (12.11.2026)

Чтобы проверить путь FAIL живьём, в установленную копию плагина временно положен испытательный рецензент:
на круге 1 он обязан вернуть CHANGES REQUESTED (MAJOR: строка «Задача #N.» в докстринге), с круга 2 —
обычный бриф. Ведущий, кодер и протокол — настоящие. После прогона плагин переустановлен чистым.

- Задача 1 (`mul`): `VERDICT … CHANGES REQUESTED` → `Agent(resume="agent-0")` — **тот же кодер** поправил
  докстринг → `Agent(resume="agent-1")` — тот же рецензент, круг 2 → APPROVED → коммит снова `resume="agent-0"`
  → приёмка PASS → DONE. Путь FAIL → правка → PASS → приёмка → DONE на родных субагентах подтверждён.
- Задача 2 (конвенции): рецензент потребовал вписать правило «Задача #N.» в конвенции. Ведущий счёл
  требование произвольным, записал отклонение D1 в DECISIONS.md и продолжил рецензента с этим решением —
  круг 2 APPROVED без правки кодера. Решение разумное, но в LEAD.md путь «ведущий снимает находку решением
  до третьего круга» прямо не описан — уточнить протокол (кандидат для V1).
