## Ограничения, которые стоит учитывать

- Режим чтения и запрет внешнего доступа задаёт хост. Изолированная копия и чистые переменные среды защищают от случайного захвата боевых данных, но сами по себе не ограничивают возможности процессов. Проба выполняется внутри фактического исполнителя. В smoke права проверены разными локальными UID; платные вызовы моделей в ревью не запускались.
- Передача записи в общий каталог Git даёт больше доступа, чем нужно только для коммита. `git-guard.py` сравнивает сохранённые отпечатки после работы, поэтому безопаснее запускать кодера в отдельном клоне или контролируемом нативном исполнителе, когда права общего Git неприемлемы.
- Восстановление шагов работает у проверок с JSON-планом, запущенных через `run-checks.py`. Для отдельных команд старого прогона, которые шли напрямую, состояние можно восстановить по их логам. Команды, явно ушедшие в свою группу процессов, должен завершать их собственный раннер.
- Начальные снимки и логи попыток сохраняются для проверки результата. Для регулярно используемых больших копий зависимостей понадобится политика хранения артефактов. Парсер вывода движка всё ещё загружает весь лог при завершении; длительные прогоны с очень большим выводом нуждаются в отдельном потоковом парсере.
- Шаблон отпечатка шага `inputs` требует полного перечня зависимых файлов. По умолчанию проверяется весь исходный снимок, что осторожнее при неизвестных связях. После обновления внешнего инструментария, который не скопирован в снимок, используйте новый id проверки.

- 52 теста общих скриптов прошли.

- Восемь регрессионных тестов 121-613 прошли на итоговых исходниках.
- Собраны и сверены пакеты Claude Code, Codex, Kimi и OpenCode версии 2.0.1. Проверены синтаксис shell и `git diff --check`.
- На связанном Git worktree проверены кодер и проверяющий под разными локальными UID, доступ к отдельной тестовой MongoDB, физическая копия Node.js-зависимостей и сборка CRA. Проверенный снимок привязан к коммиту тестового проекта.
